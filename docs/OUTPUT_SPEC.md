# doc2md 出力仕様

doc2md の出力は 2 つあります。

1. **変換結果**: `<出力先>/<元ファイル名>.md` と `<出力先>/<元ファイル名>.assets/`
2. **変換レポート**: 標準出力（または `-o`）。形式は全ツール共通の [レポート出力形式 仕様書](https://github.com/<your-org>/devtools-common/blob/main/docs/REPORT_FORMAT.md)（schema_version 1.x）

## 1. 変換結果（Markdown）

### ファイル

| パス | 内容 |
|---|---|
| `<stem>.md` | GitHub Flavored Markdown。UTF-8（BOM なし）、改行 LF、末尾に改行 1 つ |
| `<stem>.assets/<stem>-NN.<ext>` | 抽出した画像（出現順の連番 01, 02 …。同じ画像は 1 回だけ） |
| `<stem>.assets/<元ファイル名>.drawio` / `.svg` | draw.io のソースと書き出し（ペアで保管） |

- **決定的**: 同じ入力・同じオプションなら、バイト単位で同じ出力になります（時刻・乱数を含めない）。
- 再実行すると `<stem>.assets/` は作り直されます（古い画像は残りません）。
- 同じフォルダに同名（拡張子違い）のファイルがあると上書きし合うため、別の出力先を指定してください。

### 構造の約束

| 要素 | 出力 | 備考 |
|---|---|---|
| 文書 | `# <元ファイル名>`（PDF / Excel / PowerPoint / draw.io） | Word は文書内のタイトル・見出しをそのまま使う |
| 見出し | `#`〜`######` | 1 段ずつしか深くならないよう詰める（H1 の次に H3 は来ない） |
| 段落 | 1 段落 = 1 ブロック。段落内の改行は行末 `\`（ハード改行） | 連続する空白は 1 つに |
| 箇条書き | `-` / `1.`、字下げ 2 スペースで入れ子 | レベルは直前 +1 まで |
| 表 | GFM の表。**1 行目は必ず見出し行** | セル内改行は `<br>`、`\|` はエスケープ。全列が空の列は削除 |
| 画像 | `![<名前>](<stem>.assets/<stem>-NN.png)` | |
| 本文外の文字 | `> **テキストボックス**: …` / `> **SmartArt**: …` | |
| 脚注・コメント | 本文に `[^1]` / `[^e1]`（文末脚注）/ `[^c1]`（コメント）、定義は文書末尾 | コメントは `コメント（作成者）: 内容（対象:「…」）` |
| ヘッダー・フッター（Word） | 末尾に `## ヘッダー・フッター` と箇条書き | 重複は除く。`--no-header-footer` で出さない |
| ページ（PDF） | 各ページの先頭に `<!-- page N -->` | 出典を追うための HTML コメント（表示されない） |

### 形式ごとの約束

**Excel**

- シートごとに `## シート名`（非表示シートは `## シート名（非表示）`）。
- 1 シートに表が複数あるときは、表ごとに `### 表N（A4:G10）`（範囲は見出し行から最終行）。1 つなら見出しなし。
- 表の上のタイトル行・作成者行、表の下の注記（※ 等で始まる 1 セルの行）は段落として表の外に出す。
- 2 段の見出しは `親/子`（例: `金額/税抜`）。見出しの結合は全列に同じ名前を入れる。
- 本文の **縦結合** は上の値を繰り返す（検証しやすくするため）。横結合は先頭の列だけに値。
- 値の表記: 日付 `2026-04-01`、日時 `2026-04-01 09:30`、整数の小数は `1000`（`1000.0` にしない）、
  パーセント表示のセルは `10%`、真偽値は `TRUE` / `FALSE`、数式は保存されている計算結果。
- 20 万セル（`--max-cells`）を超えるブックは省メモリ読み込み: 1 シート = 1 表、結合・非表示・複数表の判定なし。

**Word**: 変更履歴は既定で「承認後」の内容（`--track-changes`）。表の縦結合は値を繰り返し、入れ子の表は
セル内に `列 / 列` を行ごとに `<br>` で並べる。

**PDF**: 見出し・箇条書き・段落の区切りは文字サイズ・太字・行頭記号・行間からの **推定**。
2 段組みは左段 → 右段の順。全ページに繰り返し出る上端・下端の行（ヘッダー・フッター・ページ番号）は除去。
OCR したページは改行を保ったまま出力する（推測で結合しない）。

## 2. 変換レポート

### meta

| キー | 型 | 内容 |
|---|---|---|
| `inputs` | 数値 | 対象ファイル数 |
| `converted` | 数値 | 変換できたファイル数 |
| `out_dir` | 文字列 | 出力先 |

### rule_id 一覧

| rule_id | severity | 意味 | 利用側の対応 |
|---|---|---|---|
| `convert.ok` | info | 変換成功。`message` に出力先、`actual` に統計（`headings= lists= tables= rows= images= chars=`、PDF 経由なら `via-pdf`） | — |
| `convert.note` | info | 形式ごとの注意事項（結合セルを埋めた、2 段組みとして読んだ 等） | 必要に応じて確認 |
| `convert.warning` | warning | 利用者が確認すべき事項（未確定の変更履歴、非表示行を含む、数式の計算結果が無い、OCR したページがある、OCR できない 等） | **内容を確認**。AI エージェントは利用者に伝える |
| `loss.headings` / `loss.list_items` / `loss.tables` / `loss.table_rows` / `loss.images` | warning | 変換時に認識した要素より出力が少ない（整形の段階で欠落） | 目視確認。不具合の可能性 |
| `loss.text` | warning | 本文の文字数が認識した量の 95% 未満 | 同上 |
| `loss.raw_text` | warning | **元ファイルから直接数えた** 文字の 95% 未満しか出力されていない（未対応の要素がある） | 図形・グラフ等を確認。`--via-pdf` と比較 |
| `convert.failed` | error | 変換に失敗（`--continue-on-error` 時のみ。それ以外は終了コード 3） | ファイルが壊れていないか確認 |

`location` は元ファイル名です。

### 終了コード

| コード | 条件 |
|---|---|
| 0 | すべて変換できた（warning があっても 0。`--strict` なら 1） |
| 1 | `convert.failed` がある、または `--strict` で warning がある |
| 2 | 未対応の形式、入力が無い、オプションの誤り、必要な外部ツール（LibreOffice 等）が無い |
| 3 | 想定外のエラー |
